Release preview: check availability before importing

This walkthrough is prepared for the next supporting release. The currently verified App Store version, 1.7.16 build 46, does not contain this importer. Do not publish this draft as an available workflow until the released build includes Google Timeline import.

In the supporting build, importing is free. Re-exporting files uses the optional lifetime purchase. Files are read locally without a Google login, upload, or place-name lookup by Whereday.

1. Export and keep your Google archive

On iPhone, follow Google’s current Timeline export instructions and save the JSON to Files. Google menus can vary during rollouts. If you already have a legacy Takeout ZIP, unzip it first and choose individual JSON files. Whereday’s importer does not accept a ZIP or an entire folder.

Retain an unchanged copy of the original. Importing a file does not move or delete Google history, and it cannot restore records absent from the archive.

2. Check which JSON you have

Each file is limited to 50 MiB and 250,000 visits plus points. Larger archives must be split before selection. Untimed waypoints are not given invented timestamps; unsupported and invalid entries appear in the preview counts.

3. Preview before saving

  1. Open Settings → Data Import → Import File and select one JSON file.
  2. Review the detected format, date range, new visits and points, duplicate counts, invalid records, and unsupported entries.
  3. Choose whether to include visits, points, or both. A raw-point archive cannot supply inferred visits.
  4. Cancel if the result is not what you expected. Preview cancellation writes nothing.
  5. Confirm only the selected records you want to add.

The importer skips approximate matches within the file and against stored records. Points match at the same rounded second within 10 metres. Visit matching uses arrival, departure, and location tolerances. Review the counts; this is not a guarantee that every semantically similar record is identical.

4. Check the destination day

Open Timeline or Map at a date represented in the archive. Check a known visit, its times, and the available route points. Retain the original while you inspect the result. Reopening the same file should show duplicates rather than offering those same records as new.

The synthetic fixture used by the existing simulator QA contains one new visit, two new points, in-file duplicates, and an invalid record. It is not personal location history. That prior simulator check does not verify this workflow in a newly released App Store binary.

If the file is rejected or looks incomplete

  • Select an extracted JSON, not its ZIP container or folder.
  • Check the size and record-count limits.
  • A valid JSON extension alone does not establish a supported Google structure.
  • Keep the source file if the parser reports missing coordinates or timestamps. Do not add invented records merely to make it import.
  • Google activity labels and every field in an archive are not promised to reproduce identically in Whereday.

For choosing a recorder, read the Google Timeline comparison. For keeping supported Whereday records afterwards, use the backup guide.
