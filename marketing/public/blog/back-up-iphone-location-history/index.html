How to back up and restore your iso.me location history

Export Visits and Points separately as iso.me JSON, check the saved files, and keep the originals when importing on another iPhone.

By Cody Bontecou, iso.me’s developer · Reviewed October 26, 2026

Keep the files before changing phones

To keep a restorable copy of iso.me location history, export Visits and Points separately as iso.me JSON files. Include the dates and fields you need, confirm both files exist, and retain the originals when importing them on another iPhone.

Recording, preview, and importing supported files are free. Writing export files requires the optional one-time unlock. This guide covers iso.me records; it is not a way to restore Apple Maps or Google Timeline archives.

Choose records, not just a file extension

A GPX track can be useful in a map viewer without being a journal backup. iso.me’s importer accepts supported iso.me visit and point exports in JSON, CSV, or Markdown. It does not accept every file that happens to have one of those extensions.

For restoration, choose Visits and Points individually. An outing summary is a different export from the visit and point records the importer expects. The export reference lists supported formats and fields.

1. Export your visits

  1. Open Export and select Visits.
  2. Select JSON. Deselect other formats if you only want this file.
  3. Choose the date range. For the full available visit archive, choose all history rather than Today or a recent period.
  4. Review time of day, minimum duration, and Only completed visits. Visit selection uses arrival time, so a stay arriving before the selected range can be excluded even if it ended inside it.
  5. Keep coordinates and the other fields you want to restore. Open Preview and check representative dates.
  6. Export to a folder you control. Note whether the settings produce one file or several dated files.

Then export your route points

Repeat the process with Points and JSON. Use the intended full date range and review its time of day, maximum accuracy, and GPS glitch filters too. Keep both sets of files. Exporting visits alone does not preserve all of the GPS points between stops.

If Preview omits expected records, follow the export filter diagnosis before writing or importing another copy.

Stop an active recording before taking a final transfer copy if you want the session to be finished first. New records captured after an export will not be in that earlier file.

2. Confirm what was saved

Open Files and find the destination you selected. Confirm that you have a visit export and a point export, not just two copies of one type. If you chose daily splitting, retain every file needed for the period.

  • Check the filenames and that the files are not empty.
  • Use Preview or a text viewer to check early and recent dates from the intended archive.
  • Keep an additional copy somewhere you will still be able to reach after changing phones.
  • Preserve the originals while transferring or importing them. Check the destination copy before relying on it.

A folder stored only on the old phone does not help if you erase that phone before transferring the files. If you choose a cloud folder or another service, that exported copy follows the destination’s storage and privacy rules. Location records can reveal detailed movements, so choose the destination deliberately.

Inspect the two JSON structures before using your own files

These examples contain invented coordinates near zero and fixed dates on January 1, 2000. They are documentation fixtures, not a real trip or captured app exports:

  • Download the synthetic Visits JSON: two named stops with arrival and departure times.
  • Download the synthetic Points JSON: three timestamped locations matching the synthetic GPX example.

In iPhone Safari, the sample links download JSON files. If your browser opens the JSON as text instead, return to this page, touch and hold the link, and choose Download Linked File. Find the saved file in Files before opening iso.me’s importer. Saving a screenshot or a copy of this article does not save the JSON records.

{
  "visits": [{
    "latitude": 0.0,
    "longitude": 0.0,
    "arrivedAt": "2000-01-01T11:45:00Z",
    "departedAt": "2000-01-01T12:00:00Z"
  }]
}

The visit file has a visits array; the route file has a points array. Visits need coordinates and an arrival time. Points need coordinates and a supported timestamp. A valid JSON file can still be unsuitable for import if those fields are missing.

Both downloadable fixtures were parsed with iso.me’s current Swift importer: two visits and three points, with their expected names, coordinates, and times. Parsing checks the file structure. The separate released-source disk check below shows how saved records can differ from these parsed counts.

Open the samples as text to inspect them. Importing them into your everyday journal would add invented records dated January 1, 2000. They are not needed to back up your own data.

The released app reconciles nearby visits after importing. In this example it retained Synthetic stop A at the first stop’s coordinates, with arrival at 11:45 UTC and departure at 12:17 UTC on January 1, 2000. It combined the two stops instead of preserving a separate stop B. The three point timestamps and coordinates remained in the saved route.

This is why you should retain the original files and compare individual records as well as totals. An import result counts the records read, not necessarily the final number of visits. Visit reconciliation is separate from a duplicate-safe archive import: repeating the point file added its three points again.

3. Import the supported files on the destination

  1. Make the saved visit and point files available in Files on the destination iPhone.
  2. Open iso.me, then choose Settings → Import file.
  3. Select a supported iso.me file and read the import result. Repeat for the other data type and any additional dated files.
  4. Check several dates on Map and Timeline. Look for both visits and route points, including the earliest and most recent records you expected.
  5. Close and reopen iso.me, then check the same dates again. Confirm the imported records remain before erasing or retiring the original phone.
  6. Keep your originals until you have checked the result. An import cannot restore records that were excluded from the export.

In App Store 1.7.16, import adds records without the newer preview and duplicate checks. Nearby visits can still be combined by visit reconciliation after import, while repeated points can be added again. Import each intended file once and inspect the result before retrying. If a file fails, retain it and read the reported format or field error before editing it. A JSON archive from Google Timeline has a different structure and is not a supported iso.me restore file.

Check the destination against the original files

  • Before importing: note the visit and point totals in Settings → Data. A phone that already has records is a merge situation, not a clean destination.
  • After each file: read the import result and check the matching record type. A successful Visits import does not prove that Points were restored.
  • Check details: compare names, notes, dates, and coordinates for a few records with the saved JSON. A total alone cannot show that the right date range was selected.
  • Check the display range: an imported record outside Today will not appear in a Today view. Select its actual date or an all-history view before importing again.

For these documentation fixtures, the checked release-source import reported two visits and three points, but saved one combined visit and three points. Use the stage-by-stage results above when inspecting the example. Keep invented records out of your everyday journal.

Restore Purchases is separate. It restores an eligible paid entitlement through the App Store; it does not download a copy of your location history. iso.me does not provide an account-based server archive or built-in iCloud journal sync.

Scheduled exports are ongoing copies, not an initial full archive

Auto Export writes the current local day to the chosen folder. It can help keep future records, but turning it on today does not by itself back up every earlier day. Make your initial full exports separately.

Background execution is best effort. Check the latest saved file, use Run Now or open the app if a scheduled copy is overdue, and confirm the records you need are present. A configured schedule is not proof that the last file was written successfully.
